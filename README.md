# kr3-responsive-shop — учебный интернет-магазин цветов

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Проект выполнен на основе HTML/CSS-проекта из КР №1 (`kr1-html-css-shop`). Bootstrap **не используется**:
вся адаптивность написана вручную (медиазапросы, Flexbox, CSS Grid).

## Описание проекта

Многостраничный сайт учебного магазина букетов: главная, каталог с боковым фильтром, страница товара,
страница заявки, контакты и страница «Доставка и оплата». Сайт корректно отображается на экранах
от 360px до широких desktop-мониторов и проверен на базовую доступность.

## Структура проекта

```
kr3-responsive-shop/
├── index.html          — главная (hero, преимущества, популярные товары, таблица услуг)
├── catalog.html        — каталог: сетка карточек, боковой фильтр, модальное окно товара
├── product.html        — страница товара: фото, таблица характеристик, похожие товары
├── order.html          — форма заявки на заказ
├── contacts.html       — контакты и форма обратной связи (модальное окно)
├── dostav.html         — доставка и оплата (страница из КР №1)
├── css/
│   ├── style.css       — базовые стили из КР №1
│   └── responsive.css  — адаптивные стили и доступность (подключается после style.css)
├── js/main.js          — меню, фильтр, формы, модальные окна, тост
├── images/             — изображения (WebP + JPG в нескольких размерах)
├── lighthouse/         — отчёт Lighthouse (Accessibility)
├── README.md
└── .gitignore
```

На каждой странице подключены стили в нужном порядке и `viewport`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<link rel="stylesheet" href="css/style.css">
<link rel="stylesheet" href="css/responsive.css">
```

## Адаптивные решения

- Файл `css/responsive.css` подключён после `style.css`, поэтому переопределяет базовые стили.
- Подход **Mobile First**: базовые правила написаны для 360px, дальше расширение через `min-width`
  (`600px`, `640px`, `768px`, `900px`, `1024px`, `1280px`).
- **Навигация (Flexbox):** на телефоне — бургер-меню (`aria-expanded`, `aria-controls`, закрытие по `Esc`
  и по клику вне меню), на планшете и desktop — горизонтальное меню.
- **Hero-блок:** на мобильном фото сверху, текст на всю ширину; на планшете и desktop текст поверх фото.
  Размер шрифта заголовков — через `clamp()`.
- **Сетка карточек (Grid):** 1 колонка → 2 колонки (от 600px) → 3 колонки (от 900px).
- **Каталог:** на мобильном фильтр над списком и сворачивается (`<details>`), на планшете фильтры в две
  колонки, на desktop (от 1024px) — боковая колонка 260px, всегда раскрытая и `sticky`.
- **Страница товара:** 1 колонка на телефоне, две колонки (фото + описание) от 768px.
- **Форма заявки:** 1 колонка на телефоне, 2 колонки от 768px; поля высотой не менее 44px,
  шрифт 16px (iOS не увеличивает страницу), кнопки на телефоне друг под другом.
- **Таблицы:** таблица характеристик в `.table-wrapper` с `overflow-x: auto` (прокручивается только
  контейнер, страница не двигается); таблица услуг на телефоне превращается в карточки (`data-label`).
- **Модальные окна:** ширина `min(100% - 24px, 560px)`, `max-height` с прокруткой внутри окна.
- **Тост** на телефоне растягивается по ширине экрана.

### Responsive images

- Базовое правило: `img, video { max-width: 100%; height: auto; }`.
- Карточки и страница товара: `<picture>` с `<source type="image/webp">` и запасным `<img>` (JPG),
  `srcset` с несколькими размерами (400w, 640w и крупнее) и `sizes`.
- У изображений заданы `width` и `height` (нет скачков вёрстки), для остальных — `loading="lazy"`.
- Hero-фон: на мобильном `hero-640`, от 768px — `hero-1200` (через `image-set()` WebP/JPG).
- Производительность: к шрифтам Google заранее устанавливается соединение (`preconnect`, без сдвига макета при подгрузке шрифта), hero-картинка
  предзагружается (`preload` с `media`), гифка тоста грузится только при первом показе, картинки ниже
  первого экрана грузятся лениво (`loading="lazy"`). Первая загрузка главной на телефоне — около 0,3 МБ
  (в версии без оптимизации — более 2 МБ).
- Размеры файлов уменьшены относительно исходных (например, `fl4`: 260 КБ → 45 КБ на телефоне).

## Исправления доступности

- Добавлена **ссылка пропуска** «Перейти к основному содержимому» (skip-link).
- Видимый **`:focus-visible`** на всех интерактивных элементах (тёмный контур 3px; на тёмных
  подложках — белый).
- **Контраст:** белый текст на розовых кнопках (1.9:1) заменён на тёмный `#432720` (7.1:1), ссылки стали тёмно-винными `#8a2d3b` (8.3:1);
  зелёный индикатор корзины, hover-состояния и полупрозрачный текст подвала исправлены; подложка
  текста в hero сделана плотнее.
- У всех полей формы есть `label`; обязательные поля помечены; ошибки показываются текстом рядом
  с полем и связаны через `aria-describedby`, `aria-invalid`; фокус переходит на первое ошибочное поле.
- У всех информативных изображений осмысленный `alt`, у декоративных — пустой `alt=""`.
- Семантика: один `h1` на странице, логичный порядок заголовков, `nav` с `aria-label`,
  `aria-current="page"` у текущей страницы и в хлебных крошках, `main` один на странице
  (убран вложенный `<main>` в каталоге, подвал вынесен из `main`).
- Кнопки корзины и «Подробнее» имеют уникальные подписи (`aria-label="Добавить в корзину: Весенний букет"`).
- Модальные окна — нативный `<dialog>` (фокус удерживается внутри, закрытие по `Esc`, кнопка закрытия 44px).
- Зоны нажатия не менее 44×44px; для таблицы-контейнера с прокруткой — `tabindex="0"` и `role="region"`.
- Учтены `prefers-reduced-motion` и `forced-colors`.
- ARIA используется только там, где её не заменяет HTML: бургер-меню, `role` у таблицы-карточек,
  `role="status"` у сообщений.

## Проверенные ширины

Проверено на 360px, 430px, 768px, 1024px и 1440px для всех страниц: горизонтальный скролл
всей страницы отсутствует (`scrollWidth == clientWidth`), шапка, навигация, hero, сетка карточек,
каталог, фильтр, страница товара, таблица, форма, контакты, подвал и модальные окна отображаются корректно.

## Самостоятельная доработка

- Бургер-меню с управлением с клавиатуры и закрытием по `Esc`.
- Сворачиваемый фильтр каталога на мобильном и sticky-фильтр на desktop.
- Таблица услуг в виде карточек на мобильном.
- `picture` с WebP/JPG, несколько размеров, разные hero-изображения для телефона и desktop.
- Skip-link, контрастные цвета, ошибки формы с `aria-describedby`, доступное модальное окно.
- Страницы `product.html` и `order.html` с предвыбором букета из ссылки (`order.html?product=...`).
